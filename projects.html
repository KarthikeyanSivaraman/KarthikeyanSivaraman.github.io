1. Support Desk AI

Done • Live Eval
GenAI Embeddings Retrieval Gemini API (Free Tier) Streamlit Pydantic Human-in-the-Loop

What It Is

A support-desk assistant that drafts cited replies for a person to approve (nothing is sent without approval). Built for property management tickets, the pipeline retrieves synthetic policies, drafts answers citing specific sections, and routes unanswerable queries or prompt injections to a person.

Retrieval architecture: Embeddings only (gemini-embedding-001). Hybrid keyword + embeddings was tested on dev (both score blending and reciprocal rank fusion) and scored lower on this data because colloquial tenant phrasings had weak keyword overlap with formal policy texts. Hybrid retrieval added noise, so it was not shipped.

Generation: Gemini Flash-Lite (gemini-flash-lite-latest) on Google AI Studio's free tier.

What Was Measured

Measured on a held-out test split of 40 hand-written synthetic tickets (30 answerable, 10 unanswerable including 3 embedded injection attempts), run once after settings were frozen on dev (EXPERIMENTS.md Section E3, eval_summary.json):

  • Right article in top 3: 30/30 (100%)
  • Required facts in the answer: 88/94 (strict string match)
  • Unanswerable routed to a person: 9/10
  • Answerable wrongly routed: 1/30
  • Injection marker absent: 3/3 (100%)
  • Drafts failed validation: 1/40 (safely routed to a person)
The honest miss & targeted fix: In ticket T39, a tenant requested a late fee waiver. The initial draft quoted the late-fee policy instead of routing the request to a person for exception handling. The prompt was revised so requests for a decision (waive a fee, refund a deduction, make an exception) now go to a person: 6 of 6 on the dev set; a fresh held-out test is pending.

Tech Stack

Python 3.11+, Streamlit, Google Gemini Developer API (gemini-flash-lite-latest, gemini-embedding-001), Pydantic schema validation, pytest. The offline demo replays real Gemini output recorded for 9 example tickets.

Snowflake Cortex Code (CoCo) Power BI Desktop TMDL DAX Data Modeling

What It Is

An end-to-end pipeline using Snowflake Cortex Code to inspect enterprise warehouse data, create star-schema views, write TMDL semantic models and DAX measures, and author 8 Power BI report visuals straight from SQL tables—without requiring Microsoft Fabric capacity or Power BI Copilot.

What Was Measured

Measured during recorded execution on TPC-H SF1 tables (take 2 + pickup recording):

  • Star-schema generation: Star schema created across FACT_ORDERS, DIM_CUSTOMER, and DIM_DATE (2,406 days matching order span).
  • Autonomous visual generation: 8 report visuals generated; automated validator reported 0 errors.

3. RAG Showdown: Vector Search Blind Spot

Shipped • Public Repo & Video
RAG Vector Search ChromaDB sentence-transformers Claude Code CLI FastAPI + React

What It Is

A controlled, reproducible investigation into top-k vector retrieval limitations on analytical counting queries ("Your RAG pipeline isn't hallucinating. It's blind."). Evaluated over 29 synthetic support tickets for a fictional subscription-box company, testing whether top-k retrieval can correctly answer: "How many tickets mention shipping delays?"

What Was Measured

Measured on a real run with ground-truth answer key:

  • Corpus: 29 support tickets (7 genuine shipping delays with varied phrasing without the keyword phrase, 3 near-miss distractors, 19 unrelated).
  • Retrieval outcome: Top-5 retrieval returned T029, T007, T018, T010, T002, missing T004 and T013. Recall: 5/7 (71.4%).
  • LLM behavior: Claude (run headless via CLI with all external tools disabled) correctly answered from the 5 tickets it received. It reported the count as 5 because top-k retrieval did not return the remaining two matches.
  • Benchmark replication: Mirrored Snowflake's published finding (standard RAG scored 5.6% on analytical search over unstructured data vs 66.7% for analytical search). Snowflake trial test confirmed error 399258 (Cortex locked on trial).

Tech Stack

Python 3.10+, sentence-transformers (all-MiniLM-L6-v2 local embeddings), Chroma in-memory vector store, Claude Code CLI (claude -p), FastAPI backend, React frontend.

5. Dataset QA (Field-Inspection Audit Pipeline)

Shipped • Local Workspace
Data Quality Python pandas PyYAML Data Contracts SHA-256 Checksums

What It Is

A rigorous data quality assurance and reconciliation pipeline for multi-round equipment field inspections. The pipeline reconciles raw CSV and Excel label logs against synthetic photo manifests, validates against explicit schema contracts, quarantines ambiguities, and packages immutable, cryptographically hashed releases.

What Was Measured

Measured on a full pipeline run over 104 synthetic label rows across 40 units, 2 sites, and 3 collection rounds:

  • Audit yield: 92 rows passed validation; 12 rows quarantined; 15 open owner questions logged.
  • Planted defects detected:
    • 2 exact duplicate rows quarantined
    • 2 near-duplicate candidates quarantined
    • 34 mixed date format instances normalized per schema policy
    • 3 missing required field rows quarantined
    • 4 photo/label orphans identified (1 label without photo, 3 photos without labels)
    • 1 score out of valid range (0-4) detected
    • 2 site conflict rows quarantined for owner resolution
  • Release integrity: Generates immutable release packages with SHA-256 checksums, refusing to overwrite existing versions.

Tech Stack

Python 3.11+, pandas, PyYAML, openpyxl, pytest, SHA-256 hashing. Zero network calls.

6. Power BI Makeover: Tidewell Coffee Co. (Fictional)

Shipped Demo • Local Workspace
Power BI Desktop PBIR TMDL DAX Data Modeling Data Visualization

What It Is

A before-and-after demonstration turning a cluttered, default-style Power BI report into a clean, on-brand executive dashboard using the same underlying CSV data. Both reports are generated from files (PBIR + TMDL) by build.py and were checked in Power BI Desktop.

Notice: Tidewell Coffee Co. is fictional, and all data was synthetically generated (seeded in build.py). This is a technical portfolio demonstration, not a client project, and no commercial services or offers are presented.

The makeover contrasts two approaches to the same CSV data:

  • Tidewell-Before.pbip: Default theme, raw column names (Sum of SalesAmt by Prod_Desc), a 12-slice pie chart, a spiky daily line chart, unrounded costs, a yellow callout box, a red title, and misaligned visuals.
  • Tidewell-After.pbip: The same CSV data rebuilt with a brand theme file (brand/tidewell-theme.json), a designed background canvas (nav rail, header in brand/tidewell-bg.png), 4 KPI cards on a 16px grid (revenue, vs target, YoY growth, gross margin), revenue vs target by month, a revenue-by-cafe chart that flags the weakest cafe, at most 3 colors, friendly field names, and real DAX measures.

The after report features insight subtitles computed directly from the data: "4 of 12 months missed target by 5% or more; worst was July (-14%)" and "Ferry Point Cafe is 34% below the average cafe".

What the Data Shows

In FY2025, revenue is up ~6% on 2024 and ~2% over target for the year, but July and August miss target by 9–14% (a summer slump built into the data). The makeover visualizes this pattern immediately so stakeholders see the operational issue in seconds.

Tech Stack & Reusable Artifacts

Power BI Desktop (PBIR report format, TMDL semantic model definition language), DAX measures, Python 3 (data generation and PBIP builder using Pillow), JSON theme specifications. Reusable artifacts include brand/tidewell-theme.json, brand/tidewell-bg.png, and MAKEOVER_CHECKLIST.md (a 60-minute step-by-step process).
